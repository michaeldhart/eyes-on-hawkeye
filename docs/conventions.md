# Conventions

*Moved out of `CLAUDE.md` so the always-loaded file stays short. Read this before adding or editing documents, entries, people, pages, layouts or styles. The Spanish version has its own file, `docs/i18n.md`. Text is unchanged.*

- Document slugs are short, undated filenames in `_documents/` (e.g. `letter-of-support.md`). Entry files are date-prefixed (`_entries/2026-07-27-utility-discussion.md`). Don't date-prefix documents; entries refer to them by slug.
- Document bodies are OCR text inside `{% raw %}<pre class="doc-text">…</pre>{% endraw %}` with `---- page N ----` markers. The `{% raw %}` wrapper is required because OCR noise can contain Liquid syntax.
- When adding documents, use `scripts/add_document.py`, then read the text and write/verify the summary and date by hand.
- Headings, button labels and document/entry titles use Title Case. Buttons that leave the page (original PDF, external source) open in a new tab with `rel="noopener"`. The external source link is generic ("View Original Source"); it isn't always the city's site.
- Contact: the Contact page links to a Google Form (`contact_form_url` in `_config.yml`), opened in a new tab. All contact, document tips and corrections go through it. The user adds Spanish to the form himself; the Spanish page points to the same form.
- Credit: the site is created and maintained by Michael Hart. Wherever his name appears, link it with `{% include author.html %}` (reads `site.author` in `_config.yml`), which opens michaeldhart.com in a new tab. Never type the name as plain text.
- Every place a summary is shown carries an AI disclosure (document page note, "AI summary" tag in the index and search fallback, note in the timeline preview). Keep this when adding new views that show summaries.
- Analytics: GoatCounter (cookieless, no personal data), site code `eyesonhawkeye` via `goatcounter_code` in `_config.yml`, same pattern as the city-county-summarizer project. The script in `_layouts/default.html` loads only in the production build (the Pages workflow), never in local previews. The About page's "What This Site Records About You" section discloses it and links to the public dashboard (https://eyesonhawkeye.goatcounter.com); the public-view setting is changed in the GoatCounter account, not in this repo. If the code is removed, the script and the claim both disappear.
- People and organizations: `_people/<slug>.md` is the registry (one file per person/org); docs and entries tag them via `people:` / `orgs:` front matter. Tag everyone who sends, receives or is substantively named in a conversation an entry summarizes, not incidental slide citations. Roles must be traceable to the records (`role_source`; say "title not stated in the records" when it isn't); no emails or phone numbers; names from the original records stay visible. New entities need a file before they can be tagged. Run `python3 scripts/check_people.py` after any tagging change (CI runs it too). Entry links from people pages go to `/timeline/#<entry-filename-without-.md>`, which the timeline opens.
- Home page overview, "What the Records Show So Far" (`index.md`, below the three columns and above Latest Documents; the user moved it down from just under the hero): short prose, every claim linked to the entry or document it comes from, same AI label as other summaries. The user approved the wording line by line (including the "What the records don't show" paragraph and the May 20, 2026 sentence), so don't reword it without asking. It is a hand-maintained summary, so when documents or entries are added, reread it and update it if the story changed, then set `overview_through` (newest record covered) and `overview_reviewed` (today) in `_config.yml`. Update the Spanish twin `es/index.md` in the same step (its wording is not yet user-approved line by line). `scripts/check_people.py` prints a warning (a GitHub Actions annotation in CI, not a failure) when a record is newer than `overview_through`. Every absence claim ("the records don't show...") must be re-verified against all documents when new ones arrive. The user worried it adds a lot of text to the home page; revisit placement or length if asked.
- Main nav collapses to a hamburger dropdown at 40rem and narrower, using the same pure-CSS checkbox pattern as the city-county-summarizer site (works without JS; the checkbox stays keyboard-focusable and Escape closes it). The link list lives in `_layouts/default.html`; add new top-level pages there.
- Accessibility (checked with axe-core in light and dark on the main page types; keep it at zero violations): every record type has a color AND a shape in `_data/types.yml` (`shape:` one of circle, square, diamond, triangle, pentagon, hexagon, octagon, cross, star) so color is never the only cue; new types need a shape. Badge backgrounds are darkened with `color-mix` so white text keeps 4.5:1. The timeline dots are an `<ol>` of 24px buttons with one roving tab stop (arrow keys, Home and End move between dots), selecting updates in place so focus is never lost, a visually hidden `role=status` line announces changes, and a "View all records as a list" alternative sits above it. The full-text `<pre>` scroll boxes on document pages are made focusable by a small script in the document layout. Links inside `.note` inherit the text color. To re-audit: serve the site, load axe-core from cdnjs in the browser pane and run it on the timeline, home, a document, people and search pages in both color schemes (emulate with the browser pane's colorScheme option; force-reload CSS between runs because the pane caches it).
- Social previews: one site-wide card (`assets/og-card.png`, made by `scripts/make_og_card.py`, names Belvidere), plus per-page titles, descriptions, canonical and og/twitter tags built in the head of `_layouts/default.html`. The user chose a single card for now; per-page cards would need timeline entries to have their own pages first (they are only dots on the timeline). Static pages need a `description:` in front matter; document descriptions come from the AI-written `summary` (so keep the first sentence self-contained). Site tagline and description in `_config.yml` name Belvidere on purpose.
- Dates display through `_includes/date.html` (handles `undated`, and uses `fdate` so Spanish pages get Spanish months). Type badges through `_includes/badge.html`.
- If you rename a type slug in `_data/types.yml`, update every document and entry that uses it.
- Use relative_url for all internal links. The site now lives at the root of https://eyesonhawkeye.com. The old github.io/eyes-on-hawkeye address redirects to it. Deploys pass the base path via the workflow, so `baseurl` stays empty. Custom domain is set in the repo's Pages settings (no CNAME file needed with Actions deploys). DNS is at GoDaddy: four A records on `@` to GitHub Pages and a `www` CNAME to michaeldhart.github.io.
